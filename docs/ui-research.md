# UI-исследование betonicum.ru (подробное)

**Дата:** июнь 2026 (ред. 2 — углублённая)
**Цель:** детально оценить интерфейс сайта по слоям, дать измеримый аудит-фреймворк и
требования к дизайн-системе.
**Связано:** [design-system.md](design-system.md) · [`site/styleguide.html`](../site/styleguide.html) ·
[ux-research.md](ux-research.md) · [market-research-and-conversion-structure.md](market-research-and-conversion-structure.md)

> **Ограничение доступа (подтверждено повторно, 3 маршрута).** Прямой доступ к betonicum.ru,
> к сайтам-дистрибьюторам и к web.archive.org из среды анализа **заблокирован** (egress-allowlist
> песочницы: `Host not in allowlist`, у архива — `unable to fetch`). Поэтому пиксельный визуальный
> разбор живого сайта невозможен. Документ даёт: (1) **методологию и чек-листы**, по которым аудит
> проводится на живом сайте за один проход; (2) **обоснованные гипотезы** текущего состояния по
> косвенным данным; (3) **бенчмарк UI-паттернов** конкурентов и индустрии. Всё, что требует
> подтверждения на сайте, помечено **[проверить]**.

## 1. Методология аудита

UI оценивается по двум осям, чтобы выводы были не «на вкус», а воспроизводимы.

### 1.1. Эвристики Нильсена (применимо к UI)
Видимость состояния системы · соответствие реальному миру (язык клиента, не «SL/TG») ·
свобода действий · консистентность и стандарты · предотвращение ошибок · узнавание вместо
припоминания · гибкость · **минималистичный эстетичный дизайн** · помощь при ошибках · документация.

### 1.2. Слои визуального аудита (10 измерений)
Сетка/композиция · цвет · типографика · компоненты и их состояния · иконки/изображения ·
формы · микровзаимодействия/motion · адаптивность · доступность (WCAG) · производительность
восприятия (скорость, порог Доэрти).

### 1.3. Шкала серьёзности находок
🔴 блокер (мешает конверсии/доступу) · 🟡 значимая · 🟢 косметика.

## 3. Аудит по слоям: гипотезы + что проверить на сайте

Каждая строка — потенциальная находка и конкретная проверка. Это и есть «протокол живого аудита».

### 3.1. Сетка и композиция
- 🟡 **Первый экран без единого УТП-фокуса** [проверить]: типичный для WP баннер-слайдер вместо
  capability-заголовка. *Проверка:* виден ли за 5 сек ответ «что/для кого/почему вы»
  (бенчмарк B2B-индустрии). *Решение:* hero c одним оффером + один primary-CTA.
- 🟡 Нет выраженной модульной сетки [проверить]. *Проверка:* выровнены ли блоки по 12-колоночной
  сетке, единый ли контейнер. *Решение:* контейнер 1200, gutter 24, грид-раскладки.

### 3.2. Цвет
- 🟡 Палитра темы по умолчанию без единого акцента [проверить]. *Проверка:* сколько разных
  цветов у кнопок/ссылок; есть ли один «цвет действия». *Решение:* один акцент = одно действие.
- 🔴 Возможен недостаточный контраст текста на фото/баннерах [проверить] (WCAG AA 4.5:1).
  *Проверка:* контраст подписей в hero и на «бетонных» подложках.

### 3.3. Типографика
- 🟡 Шрифт и шкала «из коробки» [проверить]. *Проверка:* сколько размеров/начертаний реально
  используется; есть ли иерархия H1→H3→body. *Решение:* единая шкала (Display→Caption), один гротеск.

### 3.4. Компоненты и состояния
- 🔴 **Нет единой системы кнопок** [проверить]: в WP-темах CTA разнородны. *Проверка:* собрать
  все кнопки сайта — совпадают ли форма/цвет/размер. *Решение:* компонент `.btn` + варианты.
- 🟡 Карточки систем без визуального кода [проверить]: SL/TG/SR неразличимы. *Решение:* свотчи,
  теги назначения, единая карточка.
- 🟡 Отсутствуют состояния (hover/focus/disabled/loading) [проверить]. *Решение:* матрица состояний
  (реализована в дизайн-системе v2).

### 3.5. Формы
- 🔴 Нет видимого фокуса и состояний валидации [проверить] (доступность + доверие). *Проверка:*
  табать по форме — видно ли фокус; что происходит при ошибке. *Решение:* `:focus-visible`-кольцо,
  `field--error/success`, тексты ошибок.
- 🟡 Длинные формы / неочевидный telephone [проверить]. *Решение:* короткая форма (имя+телефон),
  `tel:`-ссылка.

### 3.6. Иконки и изображения
- 🟡 Разнородная иконография/стоковые фото [проверить]. *Решение:* единый набор линейных иконок,
  реальные фото объектов с alt.

### 3.7. Микровзаимодействия / motion
- 🟢 Вероятно отсутствуют осмысленные переходы [проверить]. *Решение:* токены длительностей/изинга,
  уважение `prefers-reduced-motion`.

### 3.8. Адаптивность
- 🟡 Адаптив «из коробки» WP [проверить]: бургер, перенос форм, мелкие цели на мобайле.
  *Проверка:* тач-цели ≥ 44px, sticky-CTA. *Решение:* mobile-first ревизия.

### 3.9. Доступность (WCAG 2.1 AA)
- 🔴 Контраст, фокус, alt, размеры целей [проверить]. *Инструменты:* axe DevTools, Lighthouse a11y.

### 3.10. Производительность восприятия
- 🟡 WordPress без оптимизации часто проваливает Core Web Vitals [проверить]. *Инструменты:*
  Lighthouse, PageSpeed. *Связь:* порог Доэрти (<400 мс) — медленный сайт убивает B2B-конверсию;
  PWA-слой ([pwa-implementation.md](pwa-implementation.md)) ускоряет повторные визиты.

## 4. Бенчмарк UI: конкуренты и индустрия

### 4.1. Визуальные паттерны конкурентов (по выдаче)
| Конкурент | Паттерн | Брать? |
|---|---|---|
| ТЭОХИМ / Элакор | Плотный «каталог», много цифр доверия | Цифры — да; плотность — нет |
| ЕСП Полимер | Корпоративный, блок «контроль качества» | Блок доверия — да |
| Монтажники (tpmstroi и др.) | Крупная цена и CTA на первом экране | Явный CTA/цена — да |

### 4.2. Отраслевые B2B-эталоны (best practices)
Подтверждено внешними источниками по B2B/industrial-сайтам:
- За **5 секунд** виден ответ «что производите / кому / почему вы» — **capability-заголовок**,
  а не «инновационные решения».
- **Один primary-CTA** над линией сгиба + сигналы доверия рядом (логотипы, метрики, «масштаб»).
- Навигация **по ролям и стадии покупки**; контент сгруппирован под аудиторию.
- Норма конверсии B2B-сайта — **2–4 %**; отдельные лендинги — 5–15 %.

Вывод: рынок визуально консервативен → **отстройка = чистый, воздушный, типографически сильный
индустриальный UI** (эстетико-юзабилити эффект: аккуратнее → воспринимается надёжнее).

## 5. Протокол живого аудита (чек-лист для betonicum.ru)

Когда доступ открыт — пройти за один проход и проставить статусы:

- [ ] Hero: capability-заголовок + один primary-CTA + сигнал доверия (5-сек тест)
- [ ] Кнопки: собрать все → единый компонент? состояния hover/focus/disabled?
- [ ] Цвет: один «цвет действия»? контраст текста ≥ 4.5:1 (axe/Lighthouse)
- [ ] Типографика: иерархия H1→body, ≤ 1 гротеск, единая шкала
- [ ] Карточки систем: визуальный код (свотч/теги), «язык задачи» а не марок
- [ ] Формы: видимый фокус, валидация, короткая форма, `tel:`
- [ ] Мобайл: тач-цели ≥ 44px, sticky-CTA, бургер
- [ ] Доступность: alt у фото, фокус-кольца, контраст (axe DevTools)
- [ ] Скорость: Lighthouse Perf/CWV (LCP < 2.5с)
- [ ] Безопасность контента: нет посторонних файлов в `uploads`
